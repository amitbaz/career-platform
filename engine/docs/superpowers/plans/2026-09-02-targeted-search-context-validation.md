# Targeted Search and Candidate Context Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate Brave Search HTTP 422 failures and stop harmless Gemini structured-output variations from forcing candidate-context fallback.

**Architecture:** Keep the existing search backend/fallback and candidate-context cache architecture. Fix Brave at the HTTP request boundary by sending explicit compatibility headers and safe structured error diagnostics; fix candidate parsing by requiring known fields while ignoring unknown extras, and make the Gemini response schema enforce the same array-size limits as the parser without relaxing local type/size safeguards.

**Tech Stack:** Python 3.12, requests, dataclasses, pytest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-02-targeted-search-context-validation-design.md`

## Global Constraints

- Do not change market shares, salary floors, role targeting, Gemini model/quota configuration, Brave monthly budget, or fallback ordering.
- Never log API keys, candidate profile contents, or raw Gemini response bodies.
- Brave attempts must still be recorded before the request.
- Candidate-context fallback remains fail-open when genuinely malformed output is returned.
